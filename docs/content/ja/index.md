# Collaborate on board. Make it living in text.

livt は、オンラインホワイトボード（Miro や FigJam など）でチームが決めたことを、実例マッピングの形のままリポジトリに残し、チームの全職能の持ち物にするツールです。AI エージェントはそれを読み、BDD が目指してきた発見・定式化・自動化の流れを最後までたどれます。

## AI 時代の BDD

BDD コミュニティは、発見が定式化より、定式化が自動化より大事だと言ってきました。合意した仕様は1つの一貫した形で持ち続ける、というのもコミュニティの考えです。

ただ、実例マッピングは会話の場で終わりません。残った疑問点は開発のあいだに解消され、ルールも変わっていきます。livt は実例マッピングそのものを形式にして記録し、feature file に当たる内容を含んだまま、デザイナーやプロダクトマネージャー（PdM）を含む全職能で、完了まで追えるようにします。

AI エージェントの進化で、状況が変わりました。合意したルールの自動化は、エージェントに任せられます。テストピラミッドに沿って自動化すると、実例マッピングのルールや具体例が、別々のレイヤや言語のテストで自動化されます。livt は、そのための型とツールを CLI と AI プラグインとして渡し、レイヤや言語の違いから来る課題を、エージェントと一緒に解きます。仕様を実行して検証したいチームには、Cucumber があります。

### 課題

- 疑問点が残った実例マッピングを、完了まで持っていく場所がない
- 定式化した仕様は開発やテストの手元に置かれやすく、PdM やデザイナーなど他の職能には届きにくい
- 自動化は層や言語をまたいで散らばり、どのルールがどこで自動化されたかを追いづらい

### 顧客とユーザー

- BDD を実践したいチームの全職能（PdM、デザイナー、開発者、テスター）
- AI エージェントに実装を任せているエンジニア

### 現在の解決手段

- ルールと具体例を Gherkin に定式化し、Cucumber で実行できる仕様として自動化する
- 合意をチケットやドキュメントに書き写し、そこから先は同期しない
- ボードをそのまま残し、あとから見返す

### 解決策のアイデア

- 実例マッピングそのものを、全職能の持ち物として記録し続ける
- 自動化は AI エージェントに任せ、そのための型とツールを CLI と AI プラグインで渡す
- テストがルールを引用し、どのルールがどこで自動化されたかを集めて示す

### ユーザーは価値を得るために何をするか

- 合意したルールを AI エージェントに渡し、自動化させる
- 疑問点の解消やルールの変更を、職能を問わず同じ場所で追う
- まだ自動化されていないルールを見て、次に埋めるものを選ぶ
