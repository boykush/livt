# Collaborate on board. Make it living in text.

livt は、オンラインホワイトボード（Miro や FigJam など）でチームが決めたことを、ボードの形のままリポジトリに残し、チームの全職能の持ち物にするツールです。AI エージェントはそれを読み、BDD が目指してきた発見・定式化・自動化の流れを最後までたどれます。

[ライブデモを見る](https://boykush.github.io/livt/demo/)

[使い始める](https://github.com/boykush/livt#getting-started)

## なぜ livt か

<!-- 以下の箱は、livt 全体についての livt 自身のオポチュニティキャンバス。見出しはデモがキャンバスの箱に付けるラベルと揃える。 -->

### 課題

- 疑問点が残った実例マッピングを、完了まで持っていく場所がない
- ルールの変更は全職能の持ち物だが、feature file は開発やテストの手元に置かれやすい
- 自動化は層や言語をまたいで散らばり、どのルールがどこで自動化されたかを追いづらい

### 顧客とユーザー

- BDD を実践したいチームの全職能（PdM、デザイナー、開発者、テスター）
- AI エージェントに実装を任せているエンジニア

### 現在の解決手段

- ルールと具体例を Gherkin に定式化し、実行できる仕様として自動化する
- 合意をチケットやドキュメントに書き写し、そこから先は同期しない
- ボードをそのまま残し、あとから見返す

### 解決策のアイデア

- 実例マッピングそのものを記録し、疑問点が解消して完了するまで全職能で追える場所にする
- ルールの変更は、実例マッピングの差分として全職能が読める形で残す
- 自動化は AI エージェントに任せ、テストが引用したルールを集めて、どのルールがどこで自動化されたかを示す

### ユーザーは価値を得るために何をするか

- 合意したルールを AI エージェントに渡し、自動化させる
- 疑問点の解消やルールの変更を、職能を問わず同じ場所で追う
- まだ自動化されていないルールを見て、次に埋めるものを選ぶ
