# Collaborate on board. Make it living in text.

livt は、オンラインホワイトボード（Miro や FigJam など）でチームが決めたことを、テキストにしてリポジトリに残すツールです。AI エージェントはそのテキストを読み、BDD が目指してきた発見・定式化・自動化の流れを最後までたどれます。

[ライブデモを見る](https://boykush.github.io/livt/demo/)

## AI 時代の BDD

BDD が目指してきたのは、ルールをチームで見つけ、定式化し、テストとして自動化する一続きの流れです。定式化と自動化のあいだで人が担ってきた解釈は、いまは AI エージェントが代われます。livt は、エージェントがその流れをたどるための型を、CLI と AI プラグインとして提供します。

### 課題

- Gherkin をコードにつなぐ解釈器（Cucumber のステップ定義など）を、人が書いて保守し続けてきた
- テストピラミッドに従うと、すべてのシナリオを E2E（Large テスト）にはできない
- そのため自動化はバックエンドやフロントエンドなど実装リポジトリの各所に散らばり、どのルールがどこで自動化されたかを追えない

### 顧客とユーザー

- BDD を実践したい開発チーム
- AI エージェントに実装を任せているエンジニア

### 現在の解決手段

- Cucumber で Gherkin をステップ定義に結びつけ、テストとして実行する
- 合意をチケットに書き写し、そこから先は同期しない

### 解決策のアイデア

- ステップ定義が担っていた解釈は、AI エージェントが担う
- ルールと具体例には URI があり、テストは自動化した対象の URI を引用する
- テストはどの層・どのリポジトリにあってもよく、livt が引用を機械的に集めてルールごとの状況を示す
- 発見から定式化、自動化までの流れを、CLI と AI プラグインとして配る

### ユーザーは価値を得るために何をするか

- 合意したルールを AI エージェントに渡し、合う層のテストとして自動化させる
- まだ自動化されていないルールを見て、次に埋めるものを選ぶ
